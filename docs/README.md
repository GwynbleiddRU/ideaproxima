# Ideaproxima documentation

Three audiences, three folders:

| Folder                              | For                                                                                    | Start with                                                                                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`user/`](user/README.md)           | Everyone using the platform: contributors, scientists, funders, evaluators, moderators | [User guide](user/user-guide.md): what every object is, the exact rules it follows, how to read the numbers, roles, moderation, privacy.               |
| [`developer/`](developer/README.md) | People changing, deploying and integrating with the code                               | [Developer guide](developer/developer-guide.md), [Operations guide](developer/operations.md), [API reference](developer/api-reference.md) (generated). |
| [`agents/`](agents/README.md)       | AI agents (and maintainers) continuing the work                                        | [Agent README](agents/README.md): reading order, non-negotiable rules, decision records, domain and data-model reasoning, open questions, roadmap.     |

Elsewhere in the repository:

- [`../concept.txt`](../concept.txt): the product concept, the highest authority for direction.
- `prompts/`: **prompt sketches**, task briefs for agent work (the scoring system next; the frontend brief, now
  implemented, is kept as design guidance). A local, git-ignored folder, so it is named here rather than linked.
- [`../audit/`](../audit/README.md): the browser audit (end-to-end flows, accessibility, performance, screenshots).

The API reference (`developer/api-reference.md`) and the OpenAPI document (`developer/api/openapi.json`) are
generated by `npm run docs:api` from `packages/contracts`. The test suite fails while they are stale, and
`npm run check` verifies that every relative link in these documents resolves.
